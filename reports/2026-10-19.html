DuET: Note-Frame Dual Encoding for Piano Performance-to-Score Transcription

譜屬性掛在 note 上,拍點卻可能沒有 note onset;DuET 用雙編碼器同時學 note 級 MIDI-to-score 與 frame 級 beat／downbeat,在流行鋼琴集把 MUSTER 誤差從 6.56% 壓到 3.64%。

可轉譯 performance-to-score beat tracking positional encoding
Insight

洞見:這篇把 karaoke-jp 最頭痛的錯位講得很乾淨——譜上的屬性(音值、小節位置)是掛在 note 這個稀疏事件上的,但節拍是連續的 frame 級現象,而且拍點常常根本沒有對應的 onset。只用 note 序列就缺了節拍格線,只用 frame 就失去 note 身分。DuET 的做法是兩個編碼器各管一邊:note 編碼器做 performance MIDI-to-score,frame 編碼器做 beat／downbeat tracking,兩邊用雙向 cross-attention 互通,自回歸解碼器再輪流取用兩種表徵來輸出結構化譜屬性。另外提了 TimeRoPE 與 TPRoPE,給兩個編碼器一個共享的演奏時間座標,並把相對時間與音高關係一起編進去——這個「共享時間參考系」的設計最值得我們抄。結果上,自建的 Gangqinpu(偏流行鋼琴)MUSTER 平均誤差 6.56% → 3.64%,但在古典的 ASAP 只從 11.30% 到 11.22%,幾乎沒動。消融顯示 frame 級脈絡、時間型位置編碼、解碼器歷史遮罩都有貢獻;程式與權重已開源。

Try next

可做:把 karaoke-jp 的 mora onset 當成另一路 note 級輸入,beat／downbeat 走 frame 編碼器,用 TPRoPE 式的共享時間座標做小規模對齊實驗,看 kana 到 note 的量化誤差能不能跟著降。

重要度

Problem

把表情豐富的演奏轉成譜,必須在節拍結構裡解釋每個音的時間位置;但譜屬性附著於 note 這種稀疏事件,而拍點可能沒有任何 note onset 對應,導致 note 級與 frame 級資訊難以對齊。

Method

DuET 是雙編碼器 Transformer,聯合學習 note 級 performance MIDI-to-score(PM2S)與 frame 級 beat／downbeat tracking;兩編碼器以雙向 cross-attention 連接,自回歸解碼器交替取用兩種表徵預測結構化譜屬性。另提出 TimeRoPE 與 Time-Pitch Rotary Positional Encoding(TPRoPE),提供共享演奏時間座標並編碼相對時間與音高關係。

Data

ASAP(古典鋼琴)與作者自建的 Gangqinpu(多風格、偏流行鋼琴);評估指標為 MUSTER 平均誤差,衡量譜上時間與記譜音值。

Findings

對各資料集最強基線相比,Gangqinpu 的 MUSTER 平均誤差由 6.56% 降到 3.64%;ASAP 僅由 11.30% 降到 11.22%,增益有限。消融顯示 frame 級脈絡、時間型位置編碼與解碼器歷史遮罩皆有幫助;程式、權重與 demo 已公開。

Limitations

輸入是演奏 MIDI 而非音訊,要用在歌聲上還得先過一層轉錄;只做鋼琴、未涵蓋唱聲或歌詞;ASAP 上幾乎沒有提升,跨風格泛化仍待驗證;摘要未明列限制。

Editor Note

今天最貼 karaoke-jp:note 稀疏事件與 frame 連續節拍的對齊,就是 mora-to-note timing 的同一道題,而且給了可抄的共享時間座標設計。

MUSEBENCH: A Benchmark for AI-Generated Music Detection and Artifact Analysis

36 萬首規模的 AI 音樂偵測基準:涵蓋十個生成器、人機共創與對抗／壓縮／後製變體,評 11 個偵測器,並整理出三類反覆出現的生成痕跡。

貼近主線 AI-music detection artifact analysis benchmark
Insight

洞見:這篇表面是「抓 AI 音樂」的偵測基準,對 MeanAudio 這條生成線的價值其實在反面——它把生成模型留下的痕跡列成清單。作者整理出三類反覆出現的 signature:不合慣例的和聲進行、上採樣造成的頻譜週期性、以及違反物理演奏限制的細節。這三項可以直接當成我們自己的除錯檢查表:頻譜週期性是 vocoder／codec 上採樣階段的鍋,和聲不合慣例指向條件與資料分佈,違反物理限制則是長時連貫性的問題。資料規模也值得注意:超過 36 萬首,含人類作品、十個開源與商用生成器(含 Suno、Udio)的風格對照、人機共創,以及加了對抗擾動、壓縮與聲學後製的變體;11 個偵測器在 default／out-of-domain／transformed 三種設定下評測,暴露了泛化與穩健性的弱點。限制:它量的是「可被偵測」,不是「好聽」,所以不能當品質指標用;偵測器弱點也不等於生成品質進步。

重要度

Problem

生成模型產出的音樂已逼近人類作品,是否還能可靠地分辨、以及現有偵測器在分佈外與經過後製的音訊上是否撐得住,缺乏大規模可比的基準。

Method

建立 MUSEBENCH:收錄人類作品、十個開源與商用生成器(含 Suno、Udio)的風格對照曲、人機共創作品,以及加入對抗擾動、壓縮與聲學後製的變體;在 default、out-of-domain、transformed 三種設定下評測 11 個自動偵測器的準確率、泛化與穩健性,並做聲學特徵的 artifact 分析。

Data

超過 36 萬(361K+)首曲目,含上述四類來源與變體;授權 CC BY 4.0。

Findings

報告既有偵測器的強項與弱點,並歸納出 AI 生成音樂反覆出現的痕跡:不合慣例的和聲進行、上採樣造成的頻譜週期性、違反物理演奏限制;並據此提出建構更可靠偵測系統的建議。

Limitations

量的是可偵測性而非音樂品質,不能當生成品質指標;摘要未明列限制;偵測結果受所選十個生成器版本影響,日後模型更新後痕跡清單可能失效。

Editor Note

反面讀法最有用:把它的 artifact 清單當 MeanAudio 的輸出除錯檢查表,尤其上採樣造成的頻譜週期性。
