STEMMA: Song-to-Stem Multi-Audio Reasoning for Large Audio Language Models

STEMMA 以歌曲製作的來源關係（同曲、同段落、哪些 stem 屬於哪個混音）自動建構多音訊音樂問答，微調後大型音訊語言模型的多音訊推理明顯變強。

MIR 觀點 music QA multi-audio reasoning stems
Insight

洞見:現有大型音訊語言模型與音樂 QA 資料集多半只看單一錄音，或把不相干的曲目拿來比較。STEMMA 的切入點很實用：用目錄裡的製作來源（provenance）當標籤，先指定想考的關係（是否同一首、同一段落、某個 stem 屬不屬於某個混音），再去目錄找符合與不符合的片段，因此標籤不靠人工標註也不靠模型猜。作者釋出評測用的 STEMMA-Bench 與依曲目切分的訓練集 STEMMA-Instruct，微調兩個音訊語言模型後多音訊推理提升，結構性關係進步最多，同時單音訊的音樂理解沒有退步。對 Music Flamingo 這條線，這提供了一個可以直接拿來檢驗『模型是否真的聽得出段落與人聲／伴奏關係』的基準；對 karaoke-jp 則是人聲 stem 與完整混音之間對應判斷的訓練訊號。要誠實說的是：這是 5 頁短文，摘要沒有給具體分數，是否包含歌聲或日文曲目也沒有交代。

重要度

Problem

大型音訊語言模型與音樂 QA 資料集多半只處理單一錄音，缺少需要同時比較多段音訊（同曲／同段落／stem 與混音對應）的推理評測與訓練資料。

Method

採「關係優先」的建構策略：先指定目標關係，再從目錄中找出符合與不符合的片段，標籤直接取自目錄的製作來源資訊；釋出 STEMMA-Bench（評測）與 STEMMA-Instruct（依曲目切分的訓練集）。

Data

來自音樂目錄的曲目、段落與 stem；評測集 STEMMA-Bench，訓練集 STEMMA-Instruct（track-disjoint）；微調兩個音訊語言模型。

Findings

在 STEMMA-Instruct 上微調後，多音訊推理改善，結構性關係的進步最大，且單音訊音樂理解能力得以保留。

Limitations

5 頁、1 張圖、3 個表的短文；摘要未給具體數字與所用模型名稱；未說明是否涵蓋歌聲／日文歌曲；標籤依賴目錄來源資訊，資料規模與授權未知。

MIRA: A Musical Intent Refinement Agent for Aligning Text-to-Music Generation with User Intent

文字轉音樂只靠整體 text-audio 分數看不出有沒有符合使用者意圖；MIRA 把需求拆成可驗證的 rubric，用測試時樹搜尋修改 prompt，讓開源生成器逼近商用系統。

貼近主線 text-to-music intent alignment test-time agent
Insight

洞見:CLAP 這類整體相關分數對『樂器、結構、節奏、情緒走向』等具體需求並不敏感，尤其 prompt 本身寫得含糊時。MIRA 的做法是把使用者請求拆成一組可獨立驗證的 rubric 項目（明確要求加上隱含意圖），並建立由音樂專家整理真實平台需求的 MuRA-Bench。方法上它是 test-time agent：不動生成器權重，在有限預算內把請求轉成 rubric、產生音樂、依 rubric 驗證，再用軌跡感知的樹搜尋修改 prompt。摘要稱可讓開源生成器達到接近 Suno、Mureka 的表現。對 MeanAudio 這代表一條不需重訓的評估與對齊路線，也可以和 reward alignment 實驗互補。限制是：摘要沒有給任何數字、benchmark 規模或 rubric 數量，驗證 rubric 的裁判是什麼模型也未說明，且 test-time 搜尋會增加每次生成的成本。

重要度

Problem

整體 text-audio 相關分數無法反映生成音樂是否符合使用者意圖，尤其是 prompt 不明確，或有樂器、結構、節奏、情緒走向等具體需求時。

Method

將請求轉成由可獨立驗證項目組成的 rubric（含明確要求與隱含意圖）；MIRA 為測試時 agent，對黑箱生成器在有限預算內做 prompt 修訂：生成、依 rubric 驗證、以軌跡感知的樹搜尋迭代。另提出 MuRA-Bench。

Data

MuRA-Bench：由音樂專家整理的真實平台使用者需求；評測開源與商用生成器。

Findings

摘要稱 MIRA 在開源與商用生成器上都改善意圖對齊，並讓開源生成器達到與 Suno、Mureka 等商用系統相當的水準。

Limitations

摘要未提供任何具體分數、benchmark 規模與 rubric 數量；rubric 驗證所用的裁判模型未說明；測試時搜尋增加生成成本；v1 剛上線，無 comments。

Editor Note

給 MeanAudio 的免重訓對齊思路：把 prompt 當搜尋空間、用 rubric 取代單一 CLAP 分數。數字要等讀全文才能信。
