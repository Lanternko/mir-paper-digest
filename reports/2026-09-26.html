DriftAudio: Marginal Drifting for Distributional Post-Training of One-Step Text-to-Audio Generators

一步式 text-to-audio 快但分佈仍可再修；DriftAudio 在邊際音訊分佈上做 Drifting 後訓練，從 MeanAudio 出發讓 FAD 降 33.9%、FD 降 17.6%，且完全不改一步推論流程。

貼近主線 one-step TTA distributional post-training FAD/CLAP
Insight

洞見:這是今天最直接打在 MeanAudio 身上的一篇——作者的實驗起點就是 MeanAudio checkpoint。核心觀察是：一步式 TTA 把推論成本壓到極低，但生成分佈本身還有系統性偏差，而 Drifting 這類分佈式後訓練原本要「同一條件下有多筆真實樣本」才好估，free-form caption 恰恰做不到（一個 caption 往往只有一兩筆真音檔）。DriftAudio 的取捨是放棄 condition-wise、改在邊際音訊分佈上估 drifting field：在凍結的音訊特徵空間裡，用重採樣的真實樣本、一個滾動的生成樣本 bank、再加當前 batch 的生成樣本來估場，然後把這個場當成 detached 目標只更新 generator。等於是「不動 teacher、不動取樣器、不加步數」的純後訓練補丁，對 MeanAudio 這種 mean-flow 一步生成特別友善。數字上，AudioCaps 從 MeanAudio 出發 FAD 降 33.9%、FD 降 17.6%，KL 與 CLAP 同步改善；換到 FdAudio 起點時 FAD／FD／KL 仍降，但 IS 與 CLAP 出現 trade-off——這提示邊際分佈對齊會把生成拉近真實音訊的整體統計，卻不保證每個 caption 的語意貼合度都變好。對 karaoke-jp 幾乎沒有直接關聯，但「用凍結特徵空間估分佈差、只更新 generator」的招式，可以搬到人聲還原或分離後清理的一步式模型。限制:只在 AudioCaps（泛音訊事件）驗證，沒有音樂／唱聲域證據，摘要也未提聽測。

Try next

可做:直接在自家 MeanAudio checkpoint 上複刻 marginal Drifting，特徵空間先用現成 CLAP／PANNs 凍結編碼器，只跑 AudioCaps 子集看 FAD 與 CLAP 是否同向改善，再決定要不要換到音樂 caption 資料。

重要度

Problem

一步式 text-to-audio 生成器推論便宜，但生成分佈與真實分佈仍有落差；而 condition-wise 的分佈式後訓練在 free-form 文字條件下難以施行，因為單一 caption 通常只有一兩筆真實樣本可比。

Method

DriftAudio 把 Drifting 改到邊際音訊分佈上估計：在凍結的音訊特徵空間中，用重採樣真實樣本、滾動的生成樣本 bank 與當前 batch 生成樣本估出 drifting field，作為 detached 訓練目標只更新 generator，保留原本的一步推論程序與文字條件生成能力。

Data

AudioCaps；以 MeanAudio 與 FdAudio 兩個預訓練一步式生成器為起點；指標為 FAD、FD、KL、CLAP 與 IS。

Findings

從 MeanAudio 出發 FAD 與 FD 分別降 33.9% 與 17.6%，KL 與 CLAP 亦改善；從 FdAudio 出發 FAD／FD／KL 同樣下降，但 IS 與 CLAP 出現 trade-off，顯示邊際分佈對齊與條件語意貼合並非完全同向。

Limitations

僅在 AudioCaps 這類泛音訊事件資料驗證，未涉及音樂或唱聲生成；摘要未報告主觀聽測；FdAudio 起點上的 IS／CLAP 退化說明方法對「條件貼合度」沒有保證；drifting field 品質依賴凍結特徵空間的選擇，摘要未給消融。

Editor Note

今天最貼主線：別人拿 MeanAudio 當 baseline 做後訓練，而且只動 generator、不動推論步數——這是可以當天接上自家 checkpoint 的補丁型改進。

MIDIBack: Harmony-Aware Singing Pitch Correction via Joint Vocal-Accompaniment Symbolic Modeling

自動音準修正最難的是分辨「唱錯」與「表情」；MIDIBack 把人聲與伴奏事件塞進同一條 OctupleMIDI 序列做 note-level 修正，整體 RPA 78.6%，拿掉伴奏條件時 outshift 情境從 81.5% 崩到 35.8%。

可轉譯 singing pitch correction OctupleMIDI accompaniment conditioning
Insight

洞見:karaoke-jp 的評分與修音一直卡在同一個問題——pitch tracker 給你一條連續曲線，但要判斷某個音是「走音」還是「刻意的裝飾／ため」，必須知道當下的和聲脈絡。MIDIBack 的做法很直白也很對：不要只看人聲，把伴奏的 note 事件和人聲 note 事件編進同一條 OctupleMIDI 序列，讓模型在 note level 上同時看到旋律與多聲部和聲，再預測修正後的音高。最有說服力的是 ablation：在 global outshift 情境下把伴奏條件拿掉，RPA 從 81.5% 掉到 35.8%——差了兩倍多，等於直接證明「和聲脈絡不是加分項，是必要條件」。對 karaoke-jp 有兩層可用：一是評分側，note-level 的和聲感知可以讓「這句唱得準不準」判得比純 pitch 距離合理；二是 mora-to-note 對齊側，既然要建 note 級別的表示，伴奏 MIDI／和弦軌就值得一起餵進去當 context，而不是只拿 vocal pitch 去貼譜。要注意這是符號域工作——輸入輸出都是 MIDI 事件，離「拿 JPOP 音檔進、修好的唱聲出」還隔著轉譯與合成兩步；而且評估用的是 6 種人工 note corruption（global outshift、learned note-dependent detuning、uniform perturbation 及其組合），不是真實歌手的走音分佈。限制:純符號域、合成劣化、僅報 RPA。

Try next

可做:在 karaoke-jp 既有 pipeline 上做最小實驗——把伴奏和弦／MIDI 軌當額外 context 餵進 note-level 音準判斷，先只做「這個 note 是否走音」的二分類，比較有／無伴奏條件的判對率，驗證 ablation 結論是否在日文 JPOP 唱段上成立。

重要度

Problem

自動音準修正（APC）必須把非刻意的走音和帶表情的音高變化分開；純人聲方法缺少顯式和聲建模，既有系統又多半沒有直接使用 note 級的多聲部脈絡。

Method

提出 MIDIBack：note-level APC 框架，把人聲事件與伴奏事件聯合編碼成同一條 OctupleMIDI 序列，讓模型在符號域同時建模旋律與伴奏和聲後再修正音高。

Data

在 6 種人工 note corruption 情境下評估：global outshift、learned note-dependent detuning、uniform perturbation 及其組合；摘要未交代語料來源與規模，另有針對伴奏轉調的 case study。

Findings

整體 raw pitch accuracy（RPA）78.6%；在 global outshift 與 learned detuning 組合情境下 81.5%。移除伴奏條件後，outshift 情境 RPA 由 81.5% 降至 35.8%，顯示伴奏脈絡對修正效果起決定性作用。

Limitations

工作落在符號域（MIDI 事件），未處理音訊輸入到唱聲輸出的完整鏈路；劣化情境是人工合成而非真實歌手走音分佈；主要只報 RPA 單一指標，缺主觀聽測；摘要未說明資料規模與語言，日文唱段泛化未知。

Editor Note

給 karaoke-jp 的評分／修音側一個明確設計原則：和聲脈絡要顯式餵進去，那個 81.5% → 35.8% 的 ablation 比任何論述都有力。
